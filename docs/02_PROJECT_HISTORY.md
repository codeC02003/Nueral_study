# Project: A network that dissects a network

Two neural networks.

- **Network A — "the subject."** A 2-layer attention-only transformer trained on
  a synthetic induction task: sequences like `... a b ... a -> b` ("copy whatever
  followed this token last time"). Chosen because the correct answer is KNOWN:
  layer 0 forms a previous-token head, layer 1 forms an induction head that uses
  it. So every claim Network B makes can be graded against ground truth.

- **Network B — "the anatomist."** Reads A and works out how A does what it does,
  progressing the way human anatomy progressed: observe -> dissect -> find the
  true units -> read the blueprint -> cut and see what breaks.

## THE GOVERNING RULE — both networks are self-learning

Neither network is told what to know. Both discover it by minimising their own loss.

- **A** learns its task from data. Standard.
- **B** learns to interpret A **with a training signal that comes only from A itself.**
  No hand-written labels. No "look for an induction head." No analysis script
  dressed up as a network. If I ever have to tell B what to find, B is not
  learning — I am, and B is just plumbing.

**The known induction circuit is a HELD-OUT GRADER, never training data.**
B never sees it. We use it only afterwards, to score whether B rediscovered
the truth on its own. That separation is the difference between doing science
and marking your own homework.

Where each tier's signal comes from — all of it free, none of it hand-labelled:

| Tier | B's supervision | Source |
|---|---|---|
| 0 | match A's outputs | A's own outputs |
| 1 | reconstruct A's input from its activations | the data A already saw |
| 2 | reconstruct A's activations, sparsely | A's activations alone — fully unsupervised |
| 3 | predict properties of a population of A's | auto-generated by training many A's |
| 4 | did my ablation change A's loss? | A's loss — a reward signal, no labels at all |
| 5 | was my hypothesis confirmed? | the outcome of B's own experiments |

Tier 4 is where B stops being an observer: B proposes an intervention, A's loss
change is the reward. That is reinforcement learning where the environment is
another neural network.

## Network B's ladder

| Tier | B's access | B learns | Anatomy analogue | Field name |
|------|-----------|----------|------------------|------------|
| 0 | A's inputs & outputs | to mimic A's behavior | watching a body move | distillation |
| 1 | A's hidden activations | what info lives where | first dissections | probing classifiers |
| 2 | activations, decomposed | the true features, past superposition | **cell theory** | sparse autoencoders |
| 3 | A's raw weight matrices | properties of A from weights alone | the genome | weight-space learning |
| 4 | A, with power to intervene | to PREDICT what an intervention does, then be scored | **physiology** | causal circuit analysis |
| 5 | all of the above, in a loop | hypothesize -> test -> update | the scientific method | automated interpretability |

Tiers 0-2 are correlational (what is *present*). Tier 4 is causal (what is *used*).
The gap between those is where most interpretability projects quietly fail.

## TIER 4, SPECIFIED PROPERLY — prediction, not just ablation

An earlier version of this spec said "B proposes an ablation, A's loss change is
the reward." That is too weak, and the weakness is worth recording. Rewarding B
for finding something that *matters* rewards a salience detector: a random
direction also breaks A, so "I removed it and something changed" is a claim a
heuristic can satisfy without understanding anything.

**B must state the effect size in advance, and be scored on it.**

    B's hypothesis : "ablating feature d at layer 2 raises A's loss by 0.31 nats,
                      concentrated on tokens following `raise`"
    the experiment : run A with d zeroed; measure the actual change
    B's reward     : accuracy of the PREDICTION, not the size of the effect

This cannot be faked. Predicting the consequence of removing something requires a
model of what that thing does — including predicting *zero* for a direction A
carries but does not use, which is exactly the failure mode probes cannot detect.

Three consequences:

1. **The project acquires a number it otherwise lacks.** "The features look
   interpretable" is a judgement. B's mean prediction error is a measurement of
   how much B understands about A, and it falls as understanding improves.
2. **Correlation-vs-causation is closed structurally**, not by discipline.
3. **It is the hypothesis loop.** A prediction is a hypothesis made falsifiable.
   Reconstruction loss can never produce one; prediction error requires one.

Mapped onto anatomy's own history, which is the metaphor this project is built on:

| rung | anatomy | B's version | status |
|---|---|---|---|
| structure | dissection - what parts exist | SAE finds features | **done** |
| function | lesion studies - what a part does | ablate, observe | not built |
| mechanism | physiology - how it works | predict the effect, then test | **the target** |

Vesalius could see structure perfectly and still had the heart's function wrong.
Anatomy became a science when Harvey predicted a specific quantity and measured it.

## EXPERIMENTS ARE THE DATASET

The records of those experiments are not logs - they are the training set for the
prediction objective, and the project's real output:

    experiments/exp_000182/
        anchor.txt        which of A's checkpoints this ran against
        intervention.json what was ablated, where
        prediction.json   B's predicted effect, BEFORE the run
        result.json       what actually happened
        score.json        prediction error

This also replaces snapshot-hoarding as the storage strategy. What is worth keeping
is not "A at step 41,250" but "the experiment that established what layer 2's
exception-name direction does." Checkpoints become anchors that experiments cite.

Credit where due: the prediction-scoring objective and experiments-as-dataset came
from an external review of 01_OVERVIEW.md, and both are better than what this spec
originally said.

## Known hazards (designed around from day one)

1. **Superposition.** Neurons are polysemantic; A stores more features than it has
   neurons, as overlapping directions. Demonstrated in `lessons/demo_superposition.py`
   (20 features in 5 neurons). B must find *directions*, never "read neuron 3".
2. **Correlation != causation.** A probe decoding info from a layer does NOT mean A
   uses it. Every Tier 1-3 finding must be confirmed by a Tier 4 ablation.
3. **Weight-space symmetry.** Permute A's neurons and you get an identical function
   with different weights. A Tier 3 B must be invariant to that, or it learns noise.

### PHASE 0 · Learning the machinery (lessons 01-04)

Built the engine from scratch before touching the real project, so nothing in A
would be a black box.

| Built | Verified against |
|---|---|
| `nn/engine.py` — scalar reverse-mode autograd, ~90 lines | PyTorch to `4.44e-16` |
| `nn/tensor.py` — the same engine on numpy arrays | PyTorch, values **and** shapes |
| `nn/mlp.py`, `nn/layers.py` — Neuron/Layer/MLP | — |

**Failures, all instructive:**

- **L1: sigmoid + squared error stalls.** Left in deliberately. The model sat at
  `p = 0.000123` while the truth was 1, gradient `-7.4e-04` — functionally dead,
  because `p(1-p)` collapses when the model is confidently wrong. Cross-entropy's
  derivative cancels that factor exactly: **4,053x** the gradient. This is why A's
  output layer uses cross-entropy.
- **L2: I skipped a node in the manual backward walk** and `w.grad` silently stayed
  `0.000000`. The canonical backprop bug: no crash, no warning, a parameter that
  never learns.
- **L2: `=` instead of `+=` gives *order-dependent* wrong gradients** — reported
  `+3.0` or `+5.0` (truth: `+8.0`) depending on which branch the DFS walked first.
  Made deterministic in the lesson rather than left to luck.
- **L4: broadcasting.** Forget to sum a bias gradient back down and the bias
  silently becomes a `(4,5)` matrix — 20 numbers memorising batch position. No
  exception ever raised. Six lines (`unbroadcast`) fix it.
- **L4: the scalar engine was 95x too slow.** 693ms -> 7.3ms for the same network.

### PHASE 1 · The finding that shaped B's whole architecture

Before building B, tested the obvious plan — "B reads A's neurons."

```
20 features stored in a 5-neuron layer
neuron 3 responded to features 0,1,2,5,6,7,8,9,10,11,12,14,19
```

**Superposition.** Networks store more features than they have neurons, as
overlapping directions. Individual neurons are polysemantic. So "read neuron 3 and
say what it means" is not a fixable-with-effort plan, it is the wrong object.

**Consequence:** B must find *directions*, which is why B is a sparse autoencoder
rather than a neuron classifier. `lessons/demo_superposition.py`.

### PHASE 3 · Pruning checkpoints — two failed metrics

Goal: keep only checkpoints where A actually *changed*.

- **Attempt 1: KL divergence between A's predictions.** Failed. Adjacent
  checkpoints differ by ~0.18 nats and that barely moves across 84,000 steps
  (0.29 early, 0.17 late). The floor **is** the noise of one SGD step, so it cannot
  separate "a circuit formed" from "that batch was different". Measured, discarded.
- **Attempt 2: attention drift, but the thresholds kept 313 of 313.** Every
  checkpoint tripped it.
- **Fix:** cache a signature per checkpoint (so re-thresholding is free), sweep
  thresholds, and add a **coverage floor** so convergence cannot leave a
  34,000-step hole.

**Result: 335 -> 48 snapshots, 1.2 GB -> 264 MB**, distributed by where change
happened: every 250 steps before 12k, every 5,000 after 27k.

**Finding:** A's attention stops reorganising after ~44,000 steps (drift
0.0027 -> 0.0015, then flat). Anything watching a circuit *form* must watch the
first ~15,000 steps.

**Also: a false alarm I raised.** Free disk appeared to *drop* after deleting 1 GB.
It was a transient reading; APFS had not reclaimed yet. Corrected.

### PHASE 4 · B finds features — and one badly broken SAE

- **Failure: the SAE was not sparse.** 330 of 1024 features firing per token. It was
  doing dense reconstruction, not finding features, and the "features" it reported
  were noise.
- **Two causes:** the L1 penalty was **61x too weak**, *and* A's residual norm grows
  across layers (1.28 -> 3.08), so one `l1` means different sparsity per layer.
- **Fix:** normalise activations, then calibrate empirically:

```
   l1     active/token   recon err
0.003        113.3          2.6%   too dense - no sparsity
0.01          33.8          6.4%   <- chosen
0.03          10.4         17.2%   sparser, lossier
0.1            0.8        106.0%   collapsed
```

  The window is narrower than people expect; the table lives in `nn/sae.py` so it
  is not a magic number.

- **Failure: B's checkpoint became unloadable** when a buffer was added to the SAE.
  Fixed properly — B now detects an incompatible checkpoint and restarts cleanly. A
  system that runs for hours outlives its own code.

**Result:** 15 features firing per token, 0 dead, 15.3% reconstruction error.
Unsupervised, B found features for exception class names (`AttributeE`, `TypeE`),
the position before `None`, assignment operators, `self` as first parameter, and
byte-string literals.

### PHASE 5 · Verifying the features are causally used

Added a **write** path beside the read path in `nn/gpt.py` (15 lines) so a feature's
contribution can be removed and A re-run.

**The control is the entire result.** Deleting *any* direction hurts A, so
magnitude-matched random directions were ablated on the same batch:

```
B's features (n=40)      3.50x more damage per unit removed   Cohen d = 1.19
damage concentration     67.1% on one character (random: 8.0%)  -> 8.4x
```

Specific circuits identified: `f515` -> the `r` in `return`, `f384` -> completes
`None`, `f336` -> the dot after `self`, `f691` -> docstring quotes.

**Caveat recorded at the time:** B found the candidates; a human ran the ablations.
Evidence about A's anatomy, not evidence B understands A.

### PHASE 6 · B predicts — the target was wrong

- **Failure: R² = 0.069.** Train MAE was *exactly* `0.000000` — a 60K-parameter head
  memorising 416 samples.
- **Three fixes, all mine:** shrink to ~15K params with dropout and heavy weight
  decay; **give the head what a direction does to A's OUTPUT logits** (the largest
  single gain — it had been getting raw 128-d vectors and inferring everything);
  and early-stop on held-out R², which had peaked at step 500 and decayed for 5,500
  more.
- **Result: R² 0.327**, and a linear ridge baseline at **−0.245** — so the structure
  learned is genuinely nonlinear.
- **But the errors had a shape:** B systematically *under-predicted* large effects
  (+0.0017 predicted where the truth was +0.0084).

### PHASE 7 · Two external reviews, and what they changed

**Review 1** proposed event-driven checkpointing (already built), delta compression,
and prediction-scoring.

- **Delta compression: tested and rejected.** The premise "you are repeatedly storing
  mostly unchanged information" is false for Adam — **92.7% of parameters change
  every 250 steps**, so the delta is dense. `gzip(delta)` = **95%** of `gzip(full)`.
  Quantised deltas give 4.5x but lossily, and the ~0.1% weight error could swamp the
  0.0015-scale drift signal the detector relies on. Pruning already gave 7x
  losslessly.
- **Prediction-scoring: adopted, and it was better than my spec.** Mine said "A's
  loss change is the reward" — that rewards a *salience detector*, which a heuristic
  can satisfy. Theirs: B states the effect size in advance and is scored on it,
  which cannot be faked. **My version was the weaker objective.**
- **Experiments-as-dataset: adopted.**

**Review 2** cut the scope hard and was right. One question, two metrics, four steps.
Its best insight — **a feature's importance is not a scalar** — was testable, so it
was tested:

```
96.3% of a feature's causal effect lands in 1% of positions
its effect where it fires is ~2,992x its effect where it doesn't
it fires on 0.72% of positions, at magnitude 2.61
```

**Diagnosis confirmed.** The R² = 0.327 failure was never a loss-function problem —
asking B for the average of a distribution that concentrated is the wrong question.
The log-target / quantile-loss debate was moot.

**arXiv:2606.09899** (HVP correction for attribution patching). I doubted the
citation; the PDF proved it real (Zhang & Wang, 5 Jun 2026) — **my skepticism was
wrong**. But it does not apply: we use *exact* ablation, and at 820K parameters that
is affordable everywhere (1,024 ablations in 18 s). Deferred with a trigger.

**Gate check — zero vs mean ablation:** ρ = 1.000, 20/20 top-20 overlap. But
diagnosed *why*: features fire on 0.72% of positions at magnitude 2.61, so the mean
they clamp to is 0.016 and the two interventions are nearly the same operation.
**Weaker evidence than it looks** — recorded as such.

### PHASE 8 · V2 — the corrected experiment

**Step 1.** Rebuilt the dataset as `(feature, context)` rows. **452,219 rows in 105
seconds, 6.1 MB** — 440x the old dataset for the same compute, because the
per-token deltas were already being computed and thrown away. Added bootstrap CIs:
**77% of features have a CI excluding zero**, so B can now know which 23% are
indistinguishable from noise.

**Step 2-3.** Contextual target + a 5-head bootstrap ensemble for uncertainty.

**Metric 1 — PASSED.** Calibration slope **0.71 -> 1.05**, essentially unbiased at
320-400 features. R² **0.434** (with the residual state as input) against **0.327**
for the old scalar model using *all* 1,024 features.

**Metric 2 — failed, twice, and the second failure is the real one.**

- **Attempt 1** looked positive (up to 2.33x) but was invalid: the selection pool was
  821 *features* while the target was a *(feature, context)* pair. At budget 600
  random had already sampled **73%** of the pool. The test saturated before it
  measured anything. **My design error** — the selection space must match the
  prediction space.
- **Attempt 2**, selecting over 452,219 contexts: **every** active strategy lost.
  Pure uncertainty got *worse* with more data (MAE 0.152 -> 0.237) — the classic
  pathology, max-disagreement selects outliers and the training distribution drifts.

**Four diagnostics:**

1. Noise? **No.** Repeating an intervention differs by exactly `0.00e+00`.
2. Input too thin? **Partly.** The 128-d residual state fixed the *bias*
   (slope 0.833 -> 0.947), R² only 0.395 -> 0.434.
3. Missing downstream information? **No.** Leaking A's layer-3 state changed nothing
   (0.413 -> 0.402) — and it *had* to, because what B needs is the *counterfactual*
   layer-3 state, which is the quantity being predicted. No shortcut around
   simulating the intervention.
4. Wrong metric? **Tested, and my hypothesis was refuted.** The target is brutally
   heavy-tailed (0.1% of rows carry 23.7% of all variance), so R² was suspect. But
   re-scoring on Spearman, log-MAE and top-1% recall, and adding a **stratified**
   sampler, still gave random the win: strat 1.00x on Spearman, 0.50x on log-MAE,
   0.95x on top-1% recall.

**Why random wins, and it is principled:** the test set is a *uniform* sample of
held-out contexts. Any non-uniform acquisition introduces train/test distribution
shift, and random sampling is the unbiased estimator of precisely the distribution
being scored. Active learning wins when labels are expensive and evaluation weights
hard cases. Here labels cost 18 seconds, and evaluation is average-case.

**The one exception, and it points at V3:** on `top1% recall` — *does B find the
genuinely most-damaging contexts?* — stratified ends **ahead** (0.3825 vs 0.3664).
That is a retrieval metric, and it is far closer to what a scientist actually wants.
**Metric 2 was probably defined wrong**, not failed.

### PHASE 9 · V3 — Metric 2 redefined, and the contradiction resolved

**Metric 2 redefined** from average prediction error to *important-mechanism
discovery*: of A's total causal effect mass, how much has B found after N
experiments? Scored on what B actually ran, normalised against an oracle.

**Result: B beats random decisively.** Predicted-magnitude selection found
**12.18% of the mass at 2,400 experiments (18.01x random, 43.5% of the oracle
bound)** and 24.85% of the true top-1% contexts (33.27x random). Random would need
~40,567 experiments to match. **Uncertainty added nothing** — hybrid was marginally
worse than pure magnitude, exactly inverting the V2 finding.

**But calibration collapsed** — slope 0.371, R² −0.276 — monotonically with how hard
a strategy chased importance. B could be a prospector or a surveyor, not both.

**Fix attempt 1: 80/20 split acquisition.** Helped, insufficiently — slope
0.371 -> 0.465. Even 50/50 stalled at 0.542.

**Why:** the loss is magnitude-weighted. The magnitude-selected rows average
**44x** larger |Δloss|, so a 20% anchor *by count* is **0.57%** of the training
*mass*. Mixing by count cannot rebalance a mass-dominated loss.

**Fix attempt 2: log-magnitude target.** Acquisition untouched; only the loss
changes. `mag80 + log` gives **slope 1.089, R² +0.120, discovery 12.45x** — better
calibrated than random acquisition ever was (|1.089−1| vs |1.302−1|) for a ~9%
relative cost in discovery. **Contradiction resolved.** It was never
explore-vs-exploit; it was a mass-weighted loss.

Recorded interaction: log targets *hurt* random acquisition (slope 2.083). Log
targets and magnitude-biased acquisition are a matched pair; neither works alone.

Detail: `findings/03_V3_RESOLVED.md`, `04_METRICS.md`.

### PHASE 10 · Validating V3 across all four layers

V3 was frozen (commit `a13d01d`, tag `v3`, `milestones/v3/`) and then re-run on
every layer of A with an **identical 40,000-step SAE budget** each.

| layer | mass ×rand | top-1% ×rand | **oracle %** | slope | R² |
|---|---|---|---|---|---|
| 0 | 5.01x | 12.5x | **39.4%** | 1.273 | 0.199 |
| 1 | 11.10x | 25.2x | **35.8%** | 1.258 | 0.095 |
| 2 | 13.76x | 29.9x | **31.4%** | 1.049 | 0.073 |
| 3 | 16.13x | 31.6x | **29.6%** | 0.577 | 0.015 |

**Discovery is not peculiar to layer 2.** Oracle % — the comparable, budget-
normalised measure — has mean 34.1%, range 29.6-39.4% (9.8 pp), CV 11.2% (population sd 3.82; sample sd 4.42 gives 13.0%). Layer 2
ranked third of four. Four layers is a small sample: the claim is "appears at every
layer tested", not "layer-invariant".

**A methodological correction fell out:** `x random` rises with depth while oracle %
falls. They move in opposite directions, because `x random` depends on how mass is
distributed in each layer's pool. Reporting only `x random` would have supported the
opposite conclusion.

**Robust to SAE budget, on layer 2:** 40k steps gave 13.76x / 31.4% oracle against
the frozen 362k-step SAE's 12.45x / 30.0%. Nine times less training, same result.
Not tested on the other layers.

**New limitation found:** calibration degrades monotonically with depth
(slope 1.273 -> 0.577, R² 0.199 -> 0.015) while discovery improves. **Discovery
generalises across depth; calibration does not** - layer 3 fails it outright.
Density correlates with the degradation, but depth, density, row count and residual
position are confounded across four layers, so the cause is not established.

Detail: `findings/04_V3_LAYER_VALIDATION.md`.

### PHASE 12 · Uncertainty quantification — hierarchical bootstrap

5,000 reps, two-level cluster resample (features, then contexts within), because
rows sharing a feature are not independent draws. The oracle bound is recomputed
inside each resampled pool.

**32 of 34 A₁-vs-A₂ comparisons overlap.** The two that don't are R² at layers 0 and
2, pointing in opposite directions - noise, and R² is the tail-dominated metric
already known to be unreliable.

**The preregistered criterion survives:** A₁ 34.5% [~30.8, ~38.2], A₂ 29.5%
[~26.7, ~32.3], band 26.1-42.1. A₂ clears the floor narrowly.

**Two of my own claims retracted:**
1. "Per-layer detail does not replicate" (Phase 11) - wrong. All per-layer CIs
   overlap; the differences are **not resolvable at this sample size**, which is
   weaker. I read structure into four noisy points, then read its absence into the
   same four.
2. The A₁ layer-3 calibration failure that drove my falsified prediction has
   bootstrap slope 0.80 **[0.56, 1.05] - includes 1.0**. It was never established
   even on A₁. Only one calibration deviation in the whole grid is resolvable:
   A₁ layer 0, 1.27 [1.05, 1.51].

**The headline gets an honest interval:** discovery advantage is roughly **9-26x**,
not "12.45x". Wide, but comfortably above 1 at every layer of both models.

**Not covered:** the bootstrap used one acquisition trajectory per model-layer while
reported figures were 3-seed means (A₁ L3 slope: 0.577 vs 0.80). Acquisition-seed
variance is an additional source these intervals exclude.

Detail: `findings/06_BOOTSTRAP_CI.md`.

periods (0.90 vs 1.10), so it is content matching, not positional memorisation —
but never produced a canonical previous-token / induction-head pair at the
preregistered 0.5 threshold (best 0.1894 and 0.1823).

Ablation showed a real two-layer critical pair, `L0H3 -> L1H3` (+11.75, +12.11 loss),
with L1H3 carrying the highest induction score (25x uniform baseline) and L0H3
**not** a previous-token head. So the model routes content matching in a
non-canonical way.

Two bugs surfaced: tiling let attempt 1 exploit periodicity instead of induction,
and a stale prior-occurrence index pointed into the filler (fixing it moved L1H3
from 0.0001 to 0.1823). Lowering the 0.5 threshold after three failures was
declined as post-hoc threshold-shopping.

**V4 is unaffected** — its claim rests on interventions against frozen A₁/A₂ and
needs no known-circuit benchmark.
